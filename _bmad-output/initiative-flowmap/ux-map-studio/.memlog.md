- (decision) Owner pain with the template map and editor: looks cobbled together, not connected, hacky like a workaround.
- (decision) Owner goal: a tool that looks complete, professional and easy to use.
- (decision) Owner reference: Atlist (atlist.com/help-center) - likes its professional look and its View/Build modes (see the map, then edit it); more complex than needed, a starting point, not to replicate.

- (decision) Entering edit: both - an Edit switch on the map shown only to users with an editing role, and the component can also be opened straight into edit mode by the integrator (prop).
- (decision) Screens: usually wide screens, sometimes laptops; the owner found Atlist's docked rail plus list plus properties layout fine on a laptop.
- (decision) No Publish step: saves are live (owner, tentative: 'I don't think at least').
- (decision) Editor item list: grouped by place (field, then pad, then what is on it), with items needing attention first; a Sort by dropdown lets the user change the order.
- (decision) Operator popup, in order: comms (and data age), 2 to 3 key values, alarms; the link to the item's page is an icon in the popup header (an open/pop-out icon), not a body button.
- (decision) Adding an item: both - kind buttons for the common kinds plus generic point, line and area tools (kind picked in the form).
- (decision) Placing an item: click the map and drag to fine-tune is the main way; typed coordinates are the backup. Address or legal land description search not chosen as a main way.
- (decision) Snapping: free drawing by default; snapping is a toggle the editor turns on (overrides the earlier snap-by-default idea; the PRD's snapping requirement stays, only its default changes).
- (decision) Undo: both - a visible Undo (button plus Ctrl+Z) for this session's changes even after they saved, and a tucked-away Recent changes panel from the edit record with revert per change.
- (decision) A bulk change undoes as one step.
