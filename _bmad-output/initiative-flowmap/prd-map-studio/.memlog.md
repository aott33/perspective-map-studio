- (decision) PRD started from the final brief (brief-flowmap) and its addendum; brief decisions are the baseline.
- (decision) Working mode: coaching path, chosen by the user before activation.
- (decision) Stakes carried from the brief: solo, two days a week, reputation goal, template-first, open-source later; calibrates the PRD to a lean solo document.
- (decision) No inputs beyond the brief and addendum.
- (decision) Concerns confirmed: public props and events contract with a breaking-change rule; edit permission split between module and page; alarm presentation review (ER-27); WCAG 2.2 accessibility; Ignition 8.3 full Gateways only with live-verified SDK claims; web form factor, desktop editing and 390 px phone point moves.
- (decision) Entry point: journey-led (user asked for a suggestion); the 30-minute field build is the hardest criterion and is a journey.
- (decision) Admin and integrator grouped as one role for common tasks (create a map for a new field, create a map for an existing field with no map UI, modify an existing map); integrator additionally mass-provisions by CSV.
- (decision) CSV import needs a template: the tool shows or exports the CSV template a user must fill, per kind.
- (decision) Entry state for building a field: the map page, empty or nearly empty. No required order of work.
- (decision) Adding an item: a form or wizard for name and properties; location typed as lat and lon or picked on the map, like setting a point in Google Maps directions.
- (decision) Correctness of a built field is judged by people (operators and other users reviewing), possibly against an overlay of another map; overlay feasibility open.
- (decision) Failure cases for UJ-1 not known to the user yet; to be elicited.
- (assumption) Conflict with brief: user says operators or field admins update properties on a phone; brief limits phones to moving points. To confirm before applying.
- (decision) Phones: move a point and edit an item's properties (option b). Overrides the brief's move-only rule; brief updated to match.
- (decision) Map items link to existing assets in the host system, so the map can later show their state.
- (decision) Reference for checking a layout: satellite imagery as a basemap, or an imported reference layer.
- (decision) Idea from user: import CSV, KML or GeoJSON, then the user selects features and maps each to an existing asset.
- (decision) Location entry: show country, province or state, and city for typed coordinates as a sanity check; a zoom-to-location action in the form.
- (decision) Snapping: visible UI difference between a snapped and a floating line end; an unconnected pipeline is not critical.
- (decision) Duplicate names: allowed when the underlying assets differ; shown with a red underline and a tooltip, not blocked.
- (decision) Losing work when leaving halfway through a big layout must be prevented: a must-have.
