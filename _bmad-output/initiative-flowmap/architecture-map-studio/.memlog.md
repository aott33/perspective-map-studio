- (decision) Paradigm: hexagonal (ports and adapters), Gateway-authoritative. The module's Gateway side owns the map store, saving, role checks and live-value subscriptions; the browser renders and edits and talks only to its Gateway delegate; the host project supplies kinds and assets through adapters it names (named query or script). Binds all epics; prevents logic split between browser, Gateway and host scripts. Owner chose option c over a Gateway-only design (a) and host-scripted design (b).
- (decision) PostgreSQL only for the map store in the first version; other databases later (owner, option a). Binds epic-map-store-and-data; prevents dialect drift.
- (decision) One map per project, rows keyed by Ignition project name; projects sharing a database connection keep separate maps in the same tables.
- (decision) Geometry stored as GeoJSON text, not a spatial type; no spatial SQL; matches import and export.
- (decision) Map Studio tables carry the prefix mapstudio_ and the module migrates them itself, recording a schema version.
- (decision) Single write path: the browser sends a finished edit with the item's version to its Gateway delegate, which checks role and version, writes, and records who and when; nothing else writes the tables, host scripts included; hosts change the map only through an API Map Studio offers.
- (decision) Kinds and assets come from project script functions the setup names (for example mapstudio.kinds() and mapstudio.assets()) returning rows in the asset contract's shape; the Gateway caches results and refreshes on a timer and on demand. Projects manage assets in the tag tree or a database, so the script adapter wraps either.
- (decision) Map Studio setup lives once per project (database connection, adapter functions, editing and phone-editing roles, refresh interval, basemap and token secret name), as a project-level setup; fallback a project script returning the setup if a custom project resource type proves too costly in the spike.
- (question) Can a module define its own project resource type in 8.3 for the setup? Unverified; the spike answers it, else the script fallback.
- (decision) Ship two example adapters in the docs (tag-tree UDT instances by type, a named-query wrapper), not as module code.
- (decision) Icon live values: one shared Gateway subscription per project to every live value the kind setups turn on, held in a latest-value cache with quality; each session gets one batch of changes per project refresh interval; batches carry the whole map, revisited at the 300-site target.
- (decision) Popups are Perspective views embedded by the component with the map item's base path as a parameter, using indirect tag bindings, so Perspective subscribes only while the popup is open (owner's idea); Map Studio ships a default popup view built from the kind setup, and a project may name its own. Replaces the pushed-on-change popup channel.

Acknowledging happens only in the built-in alarm table (alarm page or custom view); Map Studio acknowledges nothing. Docs carry an example custom view.
- (decision) Message contract: one envelope {v, type, id, body} for every browser-Gateway message; types named area.action (map.load, item.save, values.batch, popup.open, popup.close); errors as {code, message} in plain words; ids are strings, times ISO 8601 UTC, map item versions integers incremented per save; versioned with the public contract (NFR-8).

- (decision) AD-1 tightened: Map Studio reads tags only by subscription and writes only to its map store, never to tags, devices, assets or UDT instances; the host's Jython is untouched; adapter script calls run with a timeout on a bounded pool.
- (decision) AD-2 tightened: edits.apply {batchId, ops:[{op create|update|delete, entity item|kindSetup, id, baseVersion, data}]}; baseVersion 0 on create; deletes are tombstones with a version bump; a batch is all or none, one transaction, one undo step, every conflict returned; a retried batchId returns the first result; large imports go as edits.begin, edits.chunk, edits.commit under one batchId; a role-to-operation matrix on the Gateway (full: all ops; phone: point geometry and property updates and their undo only); map.load tells the browser its edit level none, phone or full.
- (decision) AD-16: the kind list comes from the host and is read only; the kind setup lives in the map store, one versioned row per project and kind id, saved through AD-2; overrides are a field of the map item saved with it; kind setups are never part of the project setup.
- (decision) AD-17: each committed batch emits one in-process change event; every open map of the project receives map.changed {seq, ops} at once, independent of values.batch; the live-value service resubscribes from the same event.
- (decision) AD-6 and AD-7 tightened: one LiveValue {value, quality, t, stale, reason} per slot with stale computed in the cache; values.batch is {seq, full, items}, full on open, on reconnect and after a link or kind setup change; default refresh 10 s; the map item object adds alarmsPath, overrides and live values, stays live while a custom view is open; placeholders are dotted paths into the map item object; a missing custom view falls back to the default popup.
- (decision) AD-18: Gateway-scope scripting functions system.mapstudio.getMap and system.mapstudio.applyEdits on the same write service; callers may supply ids (UUIDv5 from a stable name so re-runs update); an actor is required; part of the public contract; owned by epic-map-store-and-data.
- (decision) AD-19: snapping is a stored relation on the line (ends start and end referencing an item id); moving a snapped-to item moves its attached ends in the same batch through one shared geometry module; the Gateway rejects a batch that moves a snapped-to item without its ends; coordinate equality never infers snapping.
- (decision) AD-20: the map item record is closed and typed {id, kind, name, geometry, properties, assetId, overrides, ends, version, deleted}; base path, unlinked reason and unknown kind are derived at read time, never stored; properties keyed and typed by the kind list's form fields and validated by the write service; export carries ids, overrides and the exported kinds' setups; import of a known id is an update.
- (decision) AD-10 tightened: unsaved edits wait in an ordered queue in the browser's local storage per project, replayed through AD-2 with their original versions; on store-unreachable at load the tools are disabled and no map item is drawn as current; one undo stack per component session.
