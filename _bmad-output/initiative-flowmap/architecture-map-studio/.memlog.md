- (direction) Audience: the spine for builders, plus a contributor-facing architecture document for future open-source contributors, produced at Finalize.
- (decision) Paradigm: hexagonal (ports and adapters), Gateway-authoritative. The module's Gateway side owns the map store, saving, role checks and live-value subscriptions; the browser renders and edits and talks only to its Gateway delegate; the host project supplies kinds and assets through adapters it names (named query or script). Binds all epics; prevents logic split between browser, Gateway and host scripts. Owner chose option c over a Gateway-only design (a) and host-scripted design (b).
- (decision) PostgreSQL only for the map store in the first version; other databases later (owner, option a). Binds epic-map-store-and-data; prevents dialect drift.
- (decision) One map per project, rows keyed by Ignition project name; projects sharing a database connection keep separate maps in the same tables.
- (decision) Geometry stored as GeoJSON text, not a spatial type; no spatial SQL; matches import and export.
- (decision) Map Studio tables carry the prefix mapstudio_ and the module migrates them itself, recording a schema version.
- (decision) Single write path: the browser sends a finished edit with the item's version to its Gateway delegate, which checks role and version, writes, and records who and when; nothing else writes the tables, host scripts included; hosts change the map only through an API Map Studio offers.
- (decision) Kinds and assets come from project script functions the setup names (for example mapstudio.kinds() and mapstudio.assets()) returning rows in the asset contract's shape; the Gateway caches results and refreshes on a timer and on demand. Projects manage assets in the tag tree or a database, so the script adapter wraps either.
- (decision) Map Studio setup lives once per project (database connection, adapter functions, editing and phone-editing roles, refresh interval, basemap and token secret name), as a project-level setup; fallback a project script returning the setup if a custom project resource type proves too costly in the spike.
- (question) Can a module define its own project resource type in 8.3 for the setup? Unverified; the spike answers it, else the script fallback.
- (decision) Ship two example adapters in the docs (tag-tree UDT instances by type, a named-query wrapper), not as module code.
- (decision) Icon live values: one shared Gateway subscription per project to every live value the kind setups turn on, held in a latest-value cache with quality; each session gets one batch of changes per project refresh interval; batches carry the whole map, revisited at the 300-site target.
- (decision) Popups are Perspective views embedded by the component with the map item's base path as a parameter, using indirect tag bindings, so Perspective subscribes only while the popup is open (owner's idea); Map Studio ships a default popup view built from the kind setup, and a project may name its own. Replaces the pushed-on-change popup channel.
- (question) Can a third-party component embed a Perspective view (as the built-in Map's view layer does) in 8.3? Unverified; spike check.
- (decision) Popups are drawn by Map Studio itself (option b), like the Alarm Status Table's own details popup; the open popup's values are pushed from the Gateway's cache on change. Supersedes the embedded-view popup entry. Owner's call: the module should be self-contained, with no project views to supply.
- (decision) The shared per-project subscription keeps running while the Gateway runs, even with no map open; load does not grow with users. Owner deferred to the recommendation.
- (question) With a Map Studio-drawn popup, the built-in Alarm Status Table cannot sit inside it as FR-5 and UJ-5 assume; owner to choose how alarms show and where acknowledging happens.
- (decision) Popup hybrid (owner, 2026-10-26): Map Studio draws the default popup (details, comms, KPIs, alarm summary with View alarms to the project's alarm page, popup link); a kind setup may name a custom popup view, like a table row subview, which receives the documented map item object as its parameter. Acknowledging happens only in the built-in alarm table (alarm page or custom view); Map Studio acknowledges nothing. Docs carry an example custom view.
- (decision) Message contract: one envelope {v, type, id, body} for every browser-Gateway message; types named area.action (map.load, item.save, values.batch, popup.open, popup.close); errors as {code, message} in plain words; ids are strings, times ISO 8601 UTC, map item versions integers incremented per save; versioned with the public contract (NFR-8).
- (decision) Perspective client packages pinned to exact versions; the module declares its lowest supported 8.3.x; a release claims a new 8.3.x only after the template's test stack and the module's own Playwright browser suite pass on it (Mustry's e2e suite as the model).
- (decision) Docs carry proof: the Playwright suite records screenshots that the docs embed, so each documented behaviour shows evidence it works (owner).
- (decision) Signing key: the owner holds a self-signed module-signing certificate, stored as a GitHub Actions secret usable only by release jobs, with an offline backup in the owner's password manager; its fingerprint is published in the README and pinned in each host's module lock; rotation is a documented release with the new fingerprint.
- (decision) Satellite: Mapbox raster tileset mapbox.satellite through the Raster Tiles API with a public, URL-restricted token from the project's secret store, not the Standard Satellite style (built for Mapbox GL JS); billed per tile request.
- (decision) Conventions set at distill: map item ids are UUID strings created in the browser; GeoJSON longitude first, WGS 84, 6 decimals; ISO 8601 UTC in messages and timestamptz in the store; error codes stable kebab-case; Gateway loggers MapStudio.<area>, never tokens or properties in logs; no Gateway-wide module settings.
- (decision) deck.gl deferred to the flow feature; MapLibre layers draw lines and icons in the first version.
