# Map editors build and keep the map in the browser

## Description

The Map Studio tools: Edit mode entered by an Edit switch or a prop, the docked studio (mode rail, item list grouped by place, properties panel, floating draw toolbar), one clear mode, a first-run checklist, drawing and changing points, lines, areas and instruments with snapping (off by default), validation, Undo, a Recent changes dock with Revert, fast entry, item forms with the place check, linking map items to assets, and writing kind setups and overrides on the Kinds screen with a tag browser. Since the gap review of 2026-11-03 also the component's selection and viewport for the host view (a `selectedItem` prop and `onItemSelected`, `onViewportChanged`, `onPopupOpen` and `onPopupClose` events) and the phone user's own place (a "you are here" marker from the session's geolocation props bound to a prop, Locate me, Directions in the popup and the bottom sheet, Nearest to me in search). It ships as Map Studio 0.4.0 with contract 0.4.0.

## Outcome

A map editor new to the Mesa demo field lays it out with the tools alone in under 30 minutes (prd SM-2).

- R23 (parent R50; Perspective session geolocation props; owner, 2026-11-03): Where the page binds the component's `userLocation` prop to the session's `geolocation` property (the same shape: `enabled`, `permissionGranted` and `data` with latitude, longitude, accuracy, altitude, heading, speed and timestamp, so one binding does it), the map draws a "you are here" marker (a distinct dot with its accuracy ring and, when given, its heading) in a token no state uses; it is never a map item, never counted and never saved; Locate me in the zoom card moves the map to it; without a position nothing is drawn and the button says why in words (off in the session, permission not granted, no fix yet); the module reads nothing of the session itself and asks the browser for nothing.
- R24 (parent R51; owner, 2026-11-03): Where the component's `directions` prop turns it on, the popup and the phone's bottom sheet offer a Directions button on a point that opens the device's maps app at the map item's coordinates with its name (a `geo:` URI on Android, Apple Maps on iOS, Google Maps on a desktop, or the one URL template the prop names); Map Studio sends nothing to any service itself; the button is absent for a line or an area.
- R25 (parent R52): With a position known, search offers Nearest to me (the nearest map items with their distance, chosen like any result) and every Needs you row shows its distance from the user, the ranking by state unchanged.

## Constraints

- The initiative's Constraints bind here, above all NFR-2 (drawing, snapping, validation and undo in the browser, the Gateway called when an edit is finished; architecture AD-10), NFR-3 (WCAG 2.2), NFR-4 and NFR-11 (colours only from the host theme's tokens, neutral normal states), NFR-5 (editing rights checked on the Gateway on every save, AD-2; Map Studio writes only to its map store) and NFR-8 (the props, events and messages this epic adds are additive and ship as contract 0.4.0 with Map Studio 0.4.0).
- NFR-7: three Perspective SDK claims this module has not used stay unverified until the tracer checks them live on 8.3 and records them in docs/platform-checks.md: a component event declared in the descriptor reaching a Perspective event script, a prop written by the component reaching a page binding, and whether the client store exposes the session props to a component (the binding stays the contract either way).
- ER-27: the you-are-here marker's look and the distance on Needs you rows go to the engineering review before this epic's release; alarm presentation is otherwise unchanged.
- Releases follow RELEASING.md's checks by release type: 0.4.0 is minor, so one rehearsal on the template's test stack with a throwaway-signed build before the tag, the performance run (the write path and the bundle both change) and the smoke after the tag.
- Banned (EXPERIENCE.md): a Publish step, a save button, free colour pickers, blinking, a control in the bottom-right corner, a first-run tour.
- Below 768 px no drawing tools and no Kinds screen; the Edit switch is absent on the phone; phone editing is epic-phone's.

## Done when

- The Edit switch and the edit-mode prop open the docked studio for a full editor and nothing for a viewer, with exactly one named mode at any time.
- Points, lines, areas and instruments are added, changed, split, snapped, deleted and undone, each without dragging as well as with, and every finished edit saves and shows on another open map.
- A map item links to an asset, and its kind setup, written on the Kinds screen with the tag browser, drives its icon and popup at once; overrides mark and reset.
- Recent changes lists every map editor's saved changes with the values before and after, and Revert saves and is refused on a conflict.
- The page gets the selection, the viewport and the popup events and can select an item; the you-are-here marker, Locate me, Directions and Nearest to me work from the page's bindings.
- Contract 0.4.0 documents every new prop, event and message, and the three SDK checks are recorded.
- The tools meet WCAG 2.2 for dragging, target size, contrast and keyboard use at 1366 and 1440 px.
- The 30-minute test passes with an admin new to the Mesa field (prd SM-2), and the ER-27 review of the marker and the distance rows is recorded.
- Verified on the template's test stack.

## Boundaries

- Hands on: the forms, linking, undo, multi-select and properties panel that epic-import-export (the bulk form, import, export) and epic-phone (the edit sheet) reuse, and the edit record read both use.
- Where the tools sit on the page was decided in the UX workshop (ux-map-studio, 2026-10-27): Edit mode in the docked layout, direction A (R44, R47; EXPERIENCE.md).
- Not here: imports, exports, the bulk form and the Import rail item (epic-import-export, R25 to R28, R35); phone editing (epic-phone, R30, R31) and the known phone gap of a snapped-to point's move (docs/contract.md, the role matrix); transient items and stationing (epic-live-field, R53 to R59; the `dynamicItems` prop lands there, beside the props and events this epic adds); reference layers (R29, backlog).
- Not here: the kind list (read only, from the host adapter) and the Designer setup form.
