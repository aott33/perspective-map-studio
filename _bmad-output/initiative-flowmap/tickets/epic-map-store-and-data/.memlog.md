- (requirement) R1 (parent R33; prd FR-30; architecture AD-3, AD-21): On start, Map Studio creates or upgrades its `mapstudio_` tables on the PostgreSQL connection the project setup names, with no hand-written SQL, and records the schema version; it waits for the connection to become usable before it decides; every row is keyed by Ignition project name and geometry is GeoJSON text, with no spatial SQL.
- (requirement) R2 (parent R33; architecture AD-21): When the database role lacks a right or a migration fails, Map Studio logs one error naming the connection, the statement and the SQLState, leaves no half-created schema, and the map store is unavailable with that reason until fixed; a schema newer than the module makes the map read only with the reason logged; in a redundant pair only the active Gateway accepts writes.
- (requirement) R3 (parent R32, R33; architecture AD-2, AD-20): Every finished edit is one `edits.apply` batch through one write service, from the browser or the scripting API: all ops or none in one transaction, versions incremented, and who made each edit and when recorded; a retried `batchId` returns the first result; deletes are tombstones that a later batch restores.
- (requirement) R4 (parent R9; architecture AD-2, AD-5): The project setup names its full-editing and phone-editing Ignition roles; every save is checked on the Gateway against the role matrix (full editing: every op; phone editing: a point's geometry and a map item's properties, and their undo) and refused with code `role` and nothing written otherwise; `map.load` tells the browser its level (`none`, `phone`, `full`).
- (requirement) R5 (parent R34; architecture AD-2): A batch whose `baseVersion` for any map item or kind setup is not the stored version is refused whole with code `conflict`, a plain-words message and the other editor's current record, so the browser can show the other's change.
- (requirement) R6 (parent R32; architecture AD-17): Each committed batch reaches every open map of the project as `map.changed {seq, ops}` within a few seconds, without a page reload; a gap in `seq` makes the browser reload the map.
- (requirement) R7 (parent R32; architecture AD-10): Unsaved batches wait in the browser's local storage per project, in order, survive closing the browser, are replayed with their original versions until saved or discarded, and show as unsaved with the reason; when the map store is unreachable at load, the map says so, draws no map item as current, and editing is off.
- (requirement) R8 (parent R12; prd FR-9; architecture AD-4, AD-16, AD-20): The kind list (id, name, geometry, icon, form fields, label rank) comes from a project script function the setup names; adding a kind needs no module change; every map item op is validated and normalised against it (known kind, matching geometry, properties typed by the form fields) and refused with code `invalid` and the reason otherwise.
- (requirement) R9 (parent R12; prd FR-9; prd NFR-10): A core oil and gas icon set in one minimalist style, under a permissive licence with its attribution and nothing derived from OpenBridge, ships with the module for the sixteen kinds FR-9 names; a kind names its icon from it, and an unknown icon name is reported.
- (requirement) R10 (parent R13; prd FR-10; architecture AD-4): The asset list (id, name, kind, fully qualified base path) comes from a project script function the setup names; adapter calls run on a bounded pool with a timeout; the Gateway caches kinds and assets, refreshes them on a timer and on demand, and reports an empty, failing or incomplete list in words, in the Gateway log and in `map.load`.
- (requirement) R11 (architecture AD-16, AD-20; initiative Notes, Decision 2026-10-26 on build order): The map store holds one versioned kind setup per project and kind id, in a published kind setup schema carrying the parts initiative R15 names, written only through the write service and returned by `map.load` and `getMap`, so epic-viewing reads seeded kind setups before epic-editing writes them.
- (requirement) R12 (parent R9, R12, R13, R33; architecture AD-5): One setup per project, a project resource with a versioned schema, names the database connection, the kind and asset functions, the full-editing and phone-editing roles, the refresh interval (default 10 s), the alarm page, the basemaps and the token secret name; a missing or invalid setup is reported in words and leaves the map store unavailable; a changed setup applies without a Gateway restart.
- (requirement) R13 (parent R32; architecture AD-18, AD-22): Gateway-scope `system.mapstudio.getMap(project)` and `system.mapstudio.applyEdits(project, batch, actor)` run on the same write service as the browser; an actor is required; caller-supplied UUIDv5 ids make a re-run update instead of duplicate.
- (requirement) R14 (prd NFR-8; architecture AD-9): The setup schema, kind list, asset contract, kind setup schema, map item record, message types and scripting API are documented in `docs/` with examples, including two example adapters (UDT instances from the tag tree, a named-query wrapper) that follow Jython 2.7 rules, and are versioned with semantic versioning.
- (requirement) R15 (spike report, "If go: what epic 2 commits to", seed data; deferred-work, story 7 entry): The dev project's 30-pad scale set lives in the map store, written through `applyEdits`; the spike-only `testSet` prop, its stand-in data and the Scale view are removed, and the e2e suite keeps its coverage.
