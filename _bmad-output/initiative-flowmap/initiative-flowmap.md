# Map Studio for Ignition Perspective

## Description

Map Studio becomes the map of an Ignition 8.3 Perspective project: one component everyone opens, showing each site's live comms, a key value and alarms, with role-gated tools to build and edit the map in the browser and link every map item to the project's assets and tags. Its first user is the owner's `ign-scada-template`, whose Leaflet map and editor it replaces; it is built to be open-sourced once proven there. The final PRD is the source; the brief and the idea doc are upstream of it.

## Outcome

Map editors build and keep a field's map in the browser and everyone reads live state from it, shown by Map Studio replacing the template's map pages and by a newcomer laying out the demo field in under 30 minutes (prd SM-1, SM-2).

## Requirements

- R1 (prd FR-1): Every Map Studio component in a project shows the one project map, opening on the starting area it is given; two components given different starting areas show the same map items.
- R2 (prd FR-2): Point map items draw as icons with the kind's glyph, comms state, the icon KPI and alarm state (highest priority glyph, solid or hollow by acknowledgement, digit, optional count), each only where the kind setup turns it on; normal items are neutral grey.
- R3 (prd FR-3): Map item labels give way to each other as the user zooms out, ranked by the kind list, and never overlap at the starting area's zoom.
- R4 (prd FR-33): Any user finds a map item by name or asset in a search field; choosing a result zooms to it and selects it, on a 390 px phone and by keyboard.
- R5 (prd FR-34): The map shows everything the template's current map shows (line state, flow arrow on the selected line, shared markers within 20 m, Fit and Return, line and name toggles), checked against the template's docs/map.md section 5.
- R6 (prd FR-4): A click or tap on a map item opens its popup: Map Studio's default popup with the parts its kind setup turns on, in the order header (kind glyph, name, page link icon), comms with data age, 2 to 3 KPIs, alarms (ux-map-studio, 2026-10-27); values live while open and stale values marked; a bottom sheet on a 390 px phone.
- R7 (prd FR-5): Where enabled, the default popup shows an alarm summary for the map item's alarms path (counts by priority, the most important alarms in words) with a View alarms button to the project's configured alarm page; Map Studio acknowledges nothing.
- R8 (prd FR-6): Where configured, the popup link goes to a project page or URL with placeholders filled from the clicked map item, shown as an open or pop-out icon in the popup header (ux-map-studio, 2026-10-27); placeholders come from one closed list (`{item.id}`, `{item.name}`, `{asset.id}`, `{asset.path}`, `{item.properties.X}`), shared with a custom popup view's params and the alarm page, the link and the alarm page mixing text and any number of them, and a kind setup naming any other is refused when saved (owner, 2026-10-27); a placeholder with no value hides the icon.
- R9 (prd FR-7): The Map Studio tools show only for the project's editing roles (full editing and phone editing named separately), and every save is refused on the Gateway without the role.
- R10 (prd FR-8): The tools name exactly one current mode in words and a glyph, and Esc cancels drawing and returns to Select.
- R11 (prd FR-36): An empty map shows map editors in Edit mode a checklist (Set up your kinds, Add or import items, Check the operator view), each step opening its surface and ticked when done, and viewers a short note; no tour (ux-map-studio, 2026-10-27).
- R12 (prd FR-9): The project supplies the kind list (geometry, icon, form fields, label rank); a new kind needs no module change; a core oil and gas icon set in one minimalist style ships with the module.
- R13 (prd FR-10): The project supplies its asset list per a documented asset contract (at least id, name, kind, base path); the tools say where the list comes from and when it is empty or incomplete.
- R14 (prd FR-11): A map editor links or unlinks a map item to an asset; unlinked map items are allowed and counted; duplicate names for different assets are flagged, not blocked; a vanished asset or kind shows its map items as unlinked or unknown kind with the reason.
- R15 (prd FR-12): A map editor writes a kind setup once (comms path, up to 4 KPIs with one icon KPI, alarms path, popup parts, popup link, optional custom popup view with its params) relative to each base path, with an on or off switch per live value; it applies to every map item of the kind without an override; unresolved paths are reported per map item. The Kinds screen sets up only kinds the project defines, in the section order Icon, Key values, Comms, Alarms, Popup, Style rule, with a tag browser and a live preview on an item the editor chooses (ux-map-studio, 2026-10-27). The tag browser is in the first version as Map Studio's own tree, not Perspective's Tag Browse Tree component, for the full editing role only: a regular tag tree with a tag provider dropdown (the Gateway's default provider first), opened wherever an editor picks a value (key values, comms path, alarms path, a style rule's value, popup params), showing each tag's name, type and data type; in a kind's setup it opens at the preview item's asset folder (for example `[default]Mesa/P12`) and browses up and anywhere in any provider; a pick inside that folder becomes `{asset.path}/...` with "resolves for N of M items" (M the kind's map items with a base path), a pick outside it is stored as the full path with the warning "Same tag for every <kind>", and on one map item's override a pick is stored as the full path (owner, 2026-10-27; Gateway tag browse unverified until checked live).
- R16 (prd FR-13): A map editor overrides any part of the kind setup on one map item, marked as an override and resettable.
- R17 (prd FR-14): A map editor adds a point, line or area of any kind in any order, from kind buttons for the common kinds or generic point, line and area tools with the kind picked in the form (ux-map-studio, 2026-10-27), finishing by double-click, Enter or Finish, and can do it without dragging.
- R18 (prd FR-15): A map editor moves points, drags, inserts and deletes vertices, and splits a line at a point into two lines that keep kind and properties; every drag has a non-drag alternative.
- R19 (prd FR-16): Line ends and vertices snap to nearby map items and vertices with a visible indicator and a toggle, off by default (ux-map-studio, 2026-10-27); snapped and floating ends look different.
- R20 (prd FR-17): A map editor deletes without confirmation and undoes or redoes any own edit in the session by Undo and Redo always visible in Edit mode, naming the step (ux-map-studio, 2026-10-27), or Ctrl+Z and Ctrl+Shift+Z; a bulk change and an import each undo as one step; undoing a saved edit saves the reverse and is refused when another map editor changed the map item since.
- R21 (prd FR-18): A map editor duplicates a map item or adds another like the last (kind and properties copied, not the link); a ? key or button lists shortcuts.
- R22 (prd FR-19): Drawing is checked as it happens (self-intersecting areas, lines under two vertices) with plain-words messages beside the map item.
- R23 (prd FR-20): The item form shows the kind's fields, the asset picker and the location, marks missing required fields, and prefills the last values per kind except name, location and link.
- R24 (prd FR-21): A point is placed by clicking the map and dragging to fine-tune, with typed coordinates as the backup (ux-map-studio, 2026-10-27); typed coordinates show an offline place check and flag swapped or out-of-range values; Zoom to location moves the map there.
- R25 (prd FR-22): A user downloads a CSV template per kind that, filled correctly, imports with no errors.
- R26 (prd FR-23): A map editor imports CSV, KML or GeoJSON through guided steps (Preview on map and table with unreadable rows and reasons, Map columns, Match to assets, Summary of new, updated and skipped, then Import; ux-map-studio, 2026-10-27), cancellable at any step with nothing changed; the import saves as one undoable step.
- R27 (prd FR-24): An import matches rows to same-name assets, confident matches ticked and doubtful ones flagged (ux-map-studio, 2026-10-27), the rest matched by hand, with counts of linked and unlinked.
- R28 (prd FR-25): A map editor selects several map items in the item list (checkboxes, Shift-click range, select all in a group or filter) or on the map (box or lasso) and changes shared properties at once in a form showing only shared fields, with N selected and Mixed for differing values, never name, location or link (ux-map-studio, 2026-10-27); one undo step; geometry is never bulk edited.
- R29 (prd FR-26): Parked in the backlog, not covered by any epic (_bmad-output/backlog/story-reference-layers.md; owner, 2026-10-27); deferred, not dropped (ux-map-studio, 2026-10-27): a map editor shows, hides and removes a KML or GeoJSON reference layer that is never edited or saved as map items; not built in the first version.

- R35 (prd FR-35): A map editor exports the map or a selection as GeoJSON or CSV with kinds, properties and links, and an export imported into an empty map store gives the same map items.
- R36 (prd FR-32): The first version offers None, OpenStreetMap and Satellite basemaps; the Mapbox vector style option is deferred, not dropped (ux-map-studio, 2026-10-27); with none, map items draw on a blank background; tokens come from the secret store and must be public, restricted tokens.

- R41 (prd FR-40): Pipeline instruments (taps, meters, line valves) are their own map items snapped onto a line, each with its own kind setup like any point; the map store keeps which line each sits on and its distance along the line in metres from the line's start, and keeps it on the line when the line is moved, reshaped or split; a line's popup lists its instruments in order along the line with their live values, plus the line's own KPIs and alarms; a click on a line opens the popup at that line segment with the instruments at its ends highlighted; a line's style rule may use its instruments, each line segment drawing the worst of the instruments at the segment's ends; deleting a line deletes its instruments in the same save, one undo restoring both; and an instrument's alarm shows at its place on the line.

- R49 (gap review 2026-11-03, item 1; prd NFR-1, NFR-8): A read-only `viewport` prop `{center, zoom, bounds}` is updated when a move ends, and the component events `onViewportChanged` (the same shape), `onPopupOpen` (`{itemId, segment}` as `popup.open` carries it) and `onPopupClose` fire for the page; the viewport fires once per move end, never per frame, so R37's 60 frames per second hold.
- R50 (gap review 2026-11-03, item 2; Perspective session geolocation props; owner, 2026-11-03): Where the page binds the component's `userLocation` prop to the session's `geolocation` property (the module reads nothing of the session itself and asks the browser for nothing), the map draws a "you are here" marker (a distinct dot with its accuracy ring and, when the session gives one, its heading); it is never a map item, never counted and never saved; a Locate me button in the zoom card moves the map to it; without a position nothing is drawn and the button says why in words (off in the session, permission not granted, or no fix yet).
- R51 (gap review 2026-11-03, item 2; owner, 2026-11-03): Where the component's `directions` prop turns it on, the popup and the phone's bottom sheet offer a Directions button that opens the route to the map item in the device's maps app or page, from the person's current position and ready to start (owner, 2026-11-06: Apple Maps' directions link on iOS, Google Maps' directions link on Android and a desktop, or the one URL template the prop names); Map Studio sends nothing to any service itself and the button is absent for a line or an area.
- R52 (gap review 2026-11-03, item 2): With a position known, search offers Nearest to me (the nearest map items with their distance, chosen like any result) and every Needs you row shows its distance from the user, the ranking by state of R43 unchanged.
- R53 (gap review 2026-11-03, item 4; architecture AD-11, AD-20): A page feeds transient items through a `dynamicItems` prop, a list of `{id, kind, lng, lat, properties, state}` (`kind` from the project's kind list, `state` a preset name from R40's list or absent), drawn above the map items with the kind's glyph in that preset; they are never saved to the map store, never in the edit record, the export, the import or Edit mode's list, and never editable; a changed prop redraws within 100 ms (R37) and a removed id disappears.
- R54 (gap review 2026-11-03, item 4): A dynamic item with a `state` counts in Needs you under that state and its row zooms to it; one without a state counts nowhere; a click opens a popup of its name and properties (no tag values: its values come with it) and raises `onItemSelected` with a map item object marked `dynamic: true`.
- R55 (gap review 2026-11-03, item 4; architecture AD-17, AD-18): A Gateway script replaces a named layer of dynamic items on every open map of the project with `system.mapstudio.setDynamicItems(project, layer, items)`, the same shape and rules as R53, shown within one refresh interval; a layer given a `ttl` that is not refreshed in time draws its items as stale (R40's stale rule) and the function is in the versioned contract.
- R56 (gap review 2026-11-03, item 5; architecture AD-19, AD-20): A line may carry a station origin and unit (the kind setup's default per line kind, overridable per line: the station at the line's start, the unit among metres, kilometres, miles or feet stations such as `10+34.05`, and the direction along the line); where set, every place along the line (an instrument's `distanceM`, a line popup row, a marker on the line) also shows as a station in that unit and the line's popup header shows its length in it.
- R57 (gap review 2026-11-03, item 5): Search accepts a station on a named line (`L-SWD 10+34`, `L-SWD MP 12.3`, `L-SWD 1500 m`), moves the map to that point on the line and marks it until the next move; the scripting API gives `system.mapstudio.stationToPoint(project, lineId, station)` and `pointToStation(project, lineId, lng, lat)` from the shared geometry module.
- R58 (gap review 2026-11-03, item 5; architecture AD-19): A dynamic item (R53, R55) may be placed on a line by `{lineId, distanceM}` or `{lineId, station}` instead of coordinates; it draws snapped on the line at that place, keeps its place when the line is reshaped as an instrument does, and the line's popup lists it in order among the instruments with its state, so a moving pig with its ETA or a leak estimate at a post location shows where it is on the line.
- R59 (gap review 2026-11-03, item 5): A line's popup offers a distance profile strip: the line drawn straight from start to end in its station unit with every instrument and line-placed dynamic item at its place with its state glyph and each segment in the state the map draws it; a click on the strip moves the map to that place on the line.

## Constraints

- (prd NFR-2, NFR-9) Drawing and editing run in the browser and call the Gateway only when an edit is finished. Icon live values arrive per page in one batch on a refresh interval the project sets (default 10 s), never as a tag subscription per map item per session; popups are live while open; switched-off values are never read.
- (prd NFR-4, NFR-11) Colours come only from the host project's theme tokens in light and dark themes; the look is modern, minimal and clean, one minimalist icon style, neutral normal states.
- (prd NFR-5, section 5) Editing rights are checked on the Gateway on every save; tokens and credentials come from the secret store; Map Studio writes only to its map store, never to tags, devices, assets or UDT instances.
- (prd NFR-6) Ignition 8.3 full Gateways only, never Edge; Java 17 on the Gateway and the host's Jython untouched; a signed `.modl` from a GitHub release, pinned by SHA-256 and certificate fingerprint in the host's module lock and baked into its private image, never a `.modl` in git; Perspective client packages pinned to the Gateway version and every 8.3.x upgrade checked on the test stack.
- (prd NFR-7, section 10) Every Perspective client API or module SDK claim stays unverified until checked on a live 8.3 Gateway and recorded in claude-ignition-skills (open: FR-5, FR-6, FR-7, FR-12 tag browse, FR-27, FR-30, FR-32, NFR-4).
- (prd NFR-8) The component's parameters and events, the asset contract, the kind list and the CSV formats are documented and versioned with semantic versioning; a breaking change is a new major version.
- (prd NFR-10) No dependency that charges per deployment (template UX-36); permissive licences only for libraries, icons and place-check data, attributions shipped; no icon derived from the template's AGPL-window OpenBridge set.
- (prd section 4.1, section 8) State on icons, lines and popups is alarm presentation and passes the template's engineering review (ER-27) before release, with the Needs you counts, the legend's glyph key and the phone's bottom sheets for popups, a deliberate change from the template's chip row and top sheets (ux-map-studio, 2026-10-27; the properties sheet left with R31, owner 2026-11-06).
- (prd section 6.4) A one to two day spike gates all feature work; a no-go means a better page on the built-in Map instead.
- (prd sections 1 and 5) No approval workflow, Publish step, draft and release split or map version history: live saves, Undo, Recent changes with Revert, the edit record and export are the safety net (ux-map-studio, 2026-10-27).

## Done when

- The spike's go is recorded with its measures (build hours, bundle size, frame rate, batch size, phone breakage) (prd 6.4).
- The template's map and map editing run on Map Studio, the Leaflet map, `/map/edit` and `prov`'s map steps are retired, and the map lives in the map store (prd SM-1).
- A map editor new to the Mesa demo field lays it out, every map item linked, with the tools alone in under 30 minutes (prd SM-2).
- Closing the browser mid-layout loses no finished edit (prd SM-4). Phone editing (prd SM-3) is parked with R30 and R31 (owner, 2026-11-06).
- From an icon with an alarm, a viewer reaches the map item's own page in two clicks, and a normal field shows no hue (prd SM-5, SM-C2).
- A signed release is installed through the template's module lock and passes the template's engineering review of alarm presentation (prd NFR-6, ER-27).

## Boundaries

- Not a GIS, not an alarm system, no approval workflow or map version history; does not create assets or tags or write to devices; no Edge Gateways (prd section 5).
- Out for the first version: flow animation (first to revisit), the full icon library and other industries' kinds, a time slider, clustering, offline tiles, a second renderer, the open-source release, scale beyond the 30-pad set (prd 6.3); deferred, not dropped: reference layers and land grids (R29, parked in the backlog) and the Mapbox vector style basemap option (R36) (ux-map-studio, 2026-10-27), and phone editing (R30, R31, parked in the backlog; owner, 2026-11-06); dropped: the first-run tour (R11).
- Touch point: `ign-scada-template` - `/map`, `/map/edit`, `ops.mapedit`, the `map_draft` tables and queries, `prov`'s map steps, the `_Model/Map` consumers, the view generators and byte gates, the Edge example and the PV-29 harness change or retire; owner: epic-template-cutover.
- Tracer path: a project names its kinds, asset list and map store; a map editor draws a pad and links it; its kind setup binds comms, a KPI and alarms; a viewer sees the icon, opens the popup and follows its link.
