# Plain, brief words across the UI: a review of every label, hint, note and message

## Description

Asked by the owner (2026-11-11), after the Style tab's review found long and repeated sentences ("Not saved yet. This rule was not taken. Change it to send it again. The map keeps the saved rule until then."): review every description and phrase the component shows and make each clear, plain and brief.

Scope: every word a person reads in View mode and Edit mode: labels, button words, hover text and accessible descriptions, hints under fields, note boxes, the save status and its problems, the conflict, busy and store-unreachable cards, refusals written in the browser, the first-run checklist, the resolve and Live now notes, Recent changes' sentences, the tag browser when it is built, and the Designer setup form. The Gateway's refusal words are in scope where the browser shows them as they come.

For each: one idea per sentence; the same word for the same thing everywhere (saved, not stored; complete, not whole; the kind's rule); no sentence repeated in a second place on the same screen; nothing said that is only true sometimes; hover text never the only place a consequence is said; the shortest wording that still says what happens and what to do. EXPERIENCE.md's voice rules and its word list are the reference and are updated where the review settles a word.

The owner reads the list of proposed changes (old words, new words, where) before they are built, since many are asserted by tests and shown in the docs' screenshots.

Related: backlog 36 (industry-neutral words in the module's own text), which is about which nouns are used, not how briefly.
