# Changelog

Map Studio follows semantic versioning for its public contract (AD-9): the component's props and events, the message contract, the map item record, the kind list and asset contract, the kind setup schema, the project setup schema, the map store schema and the scripting API. Each contract document names the version it describes ([docs/contract.md](docs/contract.md), [docs/setup.md](docs/setup.md), [docs/kinds-and-assets.md](docs/kinds-and-assets.md), [docs/kind-setup.md](docs/kind-setup.md)), and `scripts/ci/check-contract-versions.sh` fails CI when one does not. Releases are signed `.modl` files on GitHub ([RELEASING.md](RELEASING.md)).

## 0.3.0

Unreleased: everyone reads live state from the map (epic-viewing). Contract 0.3.0; project setup schema 1; map store schema 2 (both unchanged).

### Contract changes

- New message types (epic 3 entry 5): `values.batch` (Gateway to browser: the live values of the open map's items, full after `map.load` and changes only per refresh interval, with `kindDisplay`, the path-free projection of every kind setup, on a full batch), `popup.open` and `popup.close` (browser to Gateway: the map item whose popup is open gets its values pushed on change). The LiveValue slot `{value, quality, t, stale, reason}` and the alarms slot's `{active, unacked, priority}` are in [docs/contract.md](docs/contract.md), "values.batch".
- The map draws live state (entry 5): the kind glyph, comms lost in its own theme token `--mapstudio-comms-lost` (falling back to `--qual-1`) with the glyph and the word, the icon KPI, the alarm glyph with its digit on a solid badge when unacknowledged and a hollow one when acknowledged (`--mapstudio-alarm-1` to `-3`, falling back to `--error`, `--warning`, `--info`); the default popup opens on a click (header, comms with data age, KPIs, alarms) and stays live while open. The hue tokens go to the engineering review (ER-27) in entry 12.
- The Gateway holds one subscription per project and tag path the kind setups turn on (AD-6), Alarm Metrics by Java subscription; the dev stack's Pad UDT carries a dev-only alarm for it (`ops/config/core`, a fresh volume is needed once: `ops/up.sh --fresh`).
- Basemaps (entry 6, AD-12): the setup's `basemaps` are offered in a control on the map, None (the blank background), OpenStreetMap (its public tiles) and Satellite (Mapbox satellite imagery), each with its provider's attribution always shown; `mapbox` (the vector style) stays deferred. New message types `basemap.source` and `basemap.source.reply`: the Gateway reads the Satellite token from the secret the setup's `tokenSecret` names, only when a browser asks, refuses anything but a public `pk.` token, and sends it only inside the tile URL; new error code `token-unavailable` ([docs/contract.md](docs/contract.md), "basemap.source"; [docs/basemaps.md](docs/basemaps.md)). OpenStreetMap's tile usage policy is in [docs/setup.md](docs/setup.md).
- New component prop `startingArea` (entry 6, R1): `{center: {lng, lat}, zoom, bounds: {west, south, east, north}}`, a centre and zoom or bounds to fit; the default is the whole world. It replaces the component's hard-coded start view of 0.2.0; two components on one page may open on different areas and show the same map items ([docs/contract.md](docs/contract.md), "The component's props").

- Labels, lines and the template's map parity (entry 7, R3, R5): the map's text (item names from zoom 14, the state chip "Stale" or "Comms lost" beside the name, the icon KPI from zoom 15, line name chips) is drawn by MapLibre's symbol layers in a bundled glyph source, Noto Sans SemiBold and Medium (OFL 1.1, [NOTICE](NOTICE)) rendered at build time and served at `/res/mapstudio/glyphs/` ([docs/icons.md](docs/icons.md)), with a halo, colliding and giving way by rank (the selected item, alarms by priority, comms lost, stale, then the kind list's `labelRank`); the marker image is the disc, the kind glyph, the ring and the badge with its digit, and a normal item is a dot below zoom 14 (7 px below 12) while abnormal items keep their marker. Lines take their weight from the `diameter` property with an instrument on them (3, 4, 6 px; 2 px without), a hue only from their own alarm with the glyph at the midpoint, and dash for comms lost or stale; the selected line carries the flow arrow. Points within 20 m draw as one shared marker that opens a pick list; Fit and Return sit under the zoom buttons; a tap on the ground clears the selection; Fit keeps until the items' bounds change or the user moves the map. The checklist against the template's map is [docs/map-parity.md](docs/map-parity.md) ([docs/contract.md](docs/contract.md), "What the map draws").

- The View-mode controls as designed (entry 14, R5, R10; DESIGN.md View mode, Phone, zoom-control, legend): one zoom card top-right with plus, the zoom level ("z 15"), minus, Fit and Return as glyphs (Return disabled with nothing selected), a rounded card with the floating shadow (`--mapstudio-float-shadow`, the host theme's `--boxShadow1` where it has one) and 44 px targets below 768 px; a Legend button bottom-left with MapLibre's scale bar and the provider's attribution beside it, opening a panel (by click or keyboard, Esc closes it) whose Basemap section holds entry 6's basemap choice, built from sections so entry 3 adds the glyph key and the Lines and Names toggles; nothing in the bottom-right corner. New prop `editMode` (off by default): the spike's Draw a line tool shows only where it is true (the dev `/edit` page), never in View mode ([docs/contract.md](docs/contract.md), "The component's props"; [docs/basemaps.md](docs/basemaps.md)).

- Instruments drawn on lines, the ordered line popup, segment click and the aggregate line style (entry 2, R13; AD-7, AD-11, AD-16, AD-19; [docs/instruments.md](docs/instruments.md)): an instrument (a map item of an instrument kind with an `attachment`) draws as its kind's marker at its place on its line, with a 24 px disc, its name, chip, KPI and its own alarm badge, so an instrument's alarm draws at its place while the line's own alarm keeps the midpoint badge; a line with instruments is cut in the browser at its measuring instruments (those whose kind setup has an icon KPI; a line valve bounds no segment) into one feature per segment. A line whose style rule is the instruments source (`{"instruments": "worst"}`, the kind's or an item override's) carries a new `segments` slot in `values.batch`, `[{from, to, preset, stale, reason, alarm}]`, graded on the Gateway from the instruments at each segment's ends (the worse preset, dashed when either is stale with the first named, the worse end alarm over both), its own `style` the worst over them; lines with no instrument or another rule carry none ([docs/contract.md](docs/contract.md), "The segments slot"). A click on a line opens the line's default popup at the clicked segment, 350 px wide to the popup review's padding rules (D1 to D3): header, the segment box ("Segment PT-1 to PT-2", "1.1 to 2.8 km", "398 to 371 psi - drop 27 psi over 1.7 km" or the stale words), Comms over the instruments, the instruments in order between the items the ends snap to ("CTB1 outlet", "PT-1 1.1 km", "LV-1 2 km No value", "PT-2 2.8 km", "SWD1 inlet") with live values and alarms, the open segment's two instruments highlighted in the list and ringed on the map, then the line's KPIs and alarm counts; `popup.open` gains an optional `segment {fromId, toId}` (`invalid` when malformed) and the Gateway pushes the line and every attached instrument while the popup is open; closing clears the selection. The map item object of a custom popup view gains, for a line, `instruments` in order and the open `segment`. Instrument alarms and the aggregate look go to entry 12's review (ER-27).

- The whole default popup, its link, a custom popup view and the phone bottom sheet (entry 8, R6, R7, R8, R9; AD-7): the pushed item of an open popup carries `popup: {basePath, alarmsPath, alarms}`, the alarm summary read from Ignition's alarm status for the item's alarms path (counts by priority, the most important alarms in words with their source and age; Map Studio acknowledges nothing), and `popup.open` pushes at once; `kindDisplay` carries a kind's `popupView`. The popup is the design's card (320 px, at most 480 px tall with the body scrolling, its own close, 16 px padding, a pointer in its surface, opaque above every layer) with the page link filled from the kind setup's `link` in the header (hidden when a placeholder has no value), the alarm block with **View alarms** to the setup's `alarmPage`, and, below 768 px, a bottom sheet with 44 px buttons and a footer; a kind setup's `popupView {path, params}` opens the project view instead, under a row with Map Studio's own close, with `mapItem` live and each param filled, a missing or failing view falling back to the default popup ([docs/contract.md](docs/contract.md), "The popup"; [docs/kind-setup.md](docs/kind-setup.md)). **Upgrade note:** the spike's `popupView` component prop (0.1.0) is retired and no longer read; name the view in the kind setup instead ([docs/contract.md](docs/contract.md), "The component's props"). The alarm words and the sheet go to the engineering review (ER-27) in entry 12.

- Value-driven styles and area category tints (entry 1, R12; AD-11, AD-16): a kind setup's `styleRule` is worked out on the Gateway in the shared live-value cache and reaches every open map as the preset name in a `style` slot of `values.batch` (`{preset, stale, reason}`; `normal` marked stale while the rule's source is stale, so the item draws only as stale until a fresh value); the rule's source is one more slot of the shared subscription (a `{kpi}` source shares the KPI's path), an item's `overrides.styleRule` replaces the kind's rule. The `expression` type is Ignition's own expression language with `{value}` as its one reference, parsed by the SDK's parser on the Gateway: a text that does not parse, another reference, or `tag()`, `runScript()` and `hasChanged()` are refused at save; a run that gives anything but a preset name draws `normal` with a `style` problem ([docs/kind-setup.md](docs/kind-setup.md), "Style rules as the map evaluates them"; [docs/platform-checks.md](docs/platform-checks.md), "Epic 3 entry 1"). `kindDisplay` gains each kind's path-free `styleRule` display and an area kind's `areaTints`. The map draws the presets (a point's ring and chip word, a line's hue, word, `dashed`, `dotted` and `dimmed` looks), an alarm over a value style, and an area kind's items as a closed fill in the tint its category picks, never a tint on a point or a line; the tokens `--mapstudio-attention`, `--mapstudio-warning`, `--mapstudio-fault` and `--mapstudio-tint-1` to `-6` fall back to Perspective variables and stand in until entry 12's review ([docs/styles.md](docs/styles.md), every preset and tint in both themes). New prop `previewStyles` draws the style preview panel; the bundle exports `StylePreview`, `PresetPalette` and `TintPalette` for the kind setup screen ([docs/contract.md](docs/contract.md), "The component's props").

- Search (entry 9, R4; DESIGN.md search-field, EXPERIENCE.md Search): a search field top-left (300 by 40 px, "Search sites, wells or lines") lists the map items whose name or linked asset's name holds what is typed, without regard to letter case or accents, a name that starts with the text first, then an asset name that does, then the names and asset names that hold it, at most eight rows with the kind glyph, the name and the kind (or kind and asset); an ARIA combobox chosen by click, tap or keyboard (arrows, Home, End, Enter; Esc clears and closes) that zooms to the item and selects it as a click does (a point at zoom 15 at least with its popup open, a line or area fitted); at phone width the field is the one top bar 8 px from the edges, expanding with the results, which entry 3 shares with Needs you, and the zoom card sits under it. `map.load.reply` gains `assetNames` (`[{id, name}]`, every level, no base path), so a viewer searches by asset name too ([docs/contract.md](docs/contract.md), "map.load.reply" and "Search").

## 0.2.0

The map store and its data (epic-map-store-and-data). Contract 0.2.0; project setup schema 1; map store schema 2. Requires Ignition 8.3 and a PostgreSQL connection per project.

### Contract changes

- New message types: `map.load` and `map.load.reply` (level, change sequence, map items, kind and asset lists, adapter status, read-only reason, the browser's part of the setup, `kindSetups` (levels `phone` and `full` only) and the optional `user`, the session user name), `edits.apply` and `edits.apply.reply` (one all-or-none batch of versioned ops), `map.changed` (every committed batch, to every open map of the project), `tags.browse`, `tags.browse.reply`, `tags.resolve` and `tags.resolve.reply` (the tag browser's lookups, full editors only).
- `error` (0.1.0) may now carry `batchId`, `op: {index, id}` and `conflicts`. New error codes include `conflict`, `role`, `read-only`, `store-unreachable` (also the busy reply) and `tags-unavailable`; `stale` is reserved. The full list is in [docs/contract.md](docs/contract.md), "Error codes".
- The map item record (AD-20), closed: `id`, `kind`, `name`, `geometry` (GeoJSON `Point` or `LineString`, WGS 84), `properties`, `assetId`, `overrides`, `ends`, `attachment` (schema 2), `version`, `deleted`.
- The project setup, schema version 1 ([docs/setup.md](docs/setup.md)): a project resource naming the map store connection, the full and phone editing roles, the kind and asset functions, basemaps, refresh interval, alarm page and token secret (`<provider>/<name>`, a name only).
- The kind list and asset contract ([docs/kinds-and-assets.md](docs/kinds-and-assets.md)) and the kind setup schema ([docs/kind-setup.md](docs/kind-setup.md)), including popup view params and `{asset.path}/...` tag paths.
- The scripting API `system.mapstudio`: `getMap`, `applyEdits`, `refreshAdapters`, `ping`.
- Removed: the spike-only prop `testSet`.

### Map store migrations

- Migration 1 creates the `mapstudio_` tables on the first start (needs CREATE on the connection's schema).
- Migration 2 (story 14) adds `mapstudio_item.attachment` and two indexes. `ALTER TABLE` needs the role that **owns the `mapstudio_` tables**, not the least-privilege runtime role: start the upgraded module once with the owner's role on the connection, or give the tables to the connection's role first. Until then the map store is unavailable with an error naming `migration 2` and SQLState 42501, and nothing is changed. Take a backup first ([docs/operations.md](docs/operations.md)).

### Development

- The dev stack (`ops/`) runs the Gateway as the developer's uid and gid (`IGNITION_UID` and `IGNITION_GID`, recorded in the ignored `.env` on the first run), so Designer saves to the bind-mounted `ops/project` work. A Gateway container made before this change is recreated by `ops/up.sh`.
- The `web` and `e2e` packages are at 0.2.0. Release builds take their version from the tag, and every module jar's manifest carries it as `Implementation-Version`: `mapstudio_schema_version.module_version` records the real version (the 0.2.0 rehearsal found `dev` there).
