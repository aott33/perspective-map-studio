# Changelog

Map Studio follows semantic versioning for its public contract (AD-9): the component's props and events, the message contract, the map item record, the kind list and asset contract, the kind setup schema, the project setup schema, the map store schema and the scripting API. Each contract document names the version it describes ([docs/contract.md](docs/contract.md), [docs/setup.md](docs/setup.md), [docs/kinds-and-assets.md](docs/kinds-and-assets.md), [docs/kind-setup.md](docs/kind-setup.md)), and `scripts/ci/check-contract-versions.sh` fails CI when one does not. Releases are signed `.modl` files on GitHub ([RELEASING.md](RELEASING.md)).

## 0.4.0

The map studio (epic-editing), unreleased. Contract 0.4.0; project setup schema 1; map store schema 2 (both unchanged, so no migration). Requires Ignition 8.3 and a PostgreSQL connection per project, as 0.3.0.

### Contract changes

- The page contract (epic 4 entry 2, R17, R20, R21, R48; AD-7, AD-9): the `editMode` prop is **bidirectional**. The Edit switch top-right, shown only to a session whose `map.load.reply.level` is `full`, writes it back through the component's property tree, and a value the page writes after the component mounted enters or leaves Edit mode; the component changes the mode only when the prop's value changed and differs from its own model, so its own write coming back never re-enters it. A session at level `phone` or `none` stays in View mode whatever the value, sees no switch and no studio, and the value is left as written. New prop **`selectedItem`** (a string or null), written by the component on every selection change (a marker click, a list row, a search or Needs you choice, a tap on the ground), and the component's first event, **`onItemSelected`**, declared on the descriptor (`ComponentEventDescriptor`, payload schema `mapstudio.events.json`) and fired with `{item}`: the AD-7 map item object (`{id, name, kind, assetId, properties, basePath, alarmsPath, values}`, the same a custom popup view gets as `mapItem`) or null when cleared. The page-to-component direction (the page selecting an item, the `viewport` prop, the other events) is entry 14's ([docs/contract.md](docs/contract.md), "The component's props" and "The component's events"; the SDK checks in [docs/platform-checks.md](docs/platform-checks.md), "Epic 4 entry 2").
- Edit mode is the docked studio's first slice (entry 2; DESIGN.md Layout & Spacing, EXPERIENCE.md Component Patterns): at level `full` and 768 px and wider, the mode rail (View, Items, Kinds, Layers; the last two empty until their entries), one flat item list with each item's live state badge (alarm, comms lost, stale, unlinked) from the same `values.batch` the markers draw from, the properties panel's Details tab (name, kind, latitude and longitude, the asset picker with Unlink) with every field saved when it is finished through one `edits.apply` batch, the floating toolbar with Select and Point and the mode pill naming the mode ("Add a well pad - click the map, then drag to fine-tune"), a point placed by one click and saved at once as the kind list's first point kind with that kind's name as its placeholder (a drag of the pin saves one update per drag end), and Undo and Redo in the list panel's header over one undo stack per session: one step per saved edit, last first, each named on the button ("Undo: link P31", "Undo: rename P31", "Undo: add Well pad"), each sending the reverse batch at the item's current version (a refusal names who changed it in the save status), and Redo replaying in order. The save status (Saved, Saving..., Not saved - the reason) sits in the panel header; the spike's Draw a line tool and its status line stay until entry 4's Line tool replaces them. Phone widths keep View mode; the Style tab, lines, areas, snapping, kind buttons, the Kinds screen, multi-select, Recent changes and the conflict card are later entries.

## 0.3.0

Everyone reads live state from the map (epic-viewing). Contract 0.3.0; project setup schema 1; map store schema 2 (both unchanged, so no migration). Requires Ignition 8.3 and a PostgreSQL connection per project, as 0.2.0.

### Contract changes

- New message types (epic 3 entry 5): `values.batch` (Gateway to browser: the live values of the open map's items, full after `map.load` and changes only per refresh interval, with `kindDisplay`, the path-free projection of every kind setup, on a full batch), `popup.open` and `popup.close` (browser to Gateway: the map item whose popup is open gets its values pushed on change). The LiveValue slot `{value, quality, t, stale, reason}` and the alarms slot's `{active, unacked, priority}` are in [docs/contract.md](docs/contract.md), "values.batch".
- The map draws live state (entry 5): the kind glyph, comms lost in its own theme token `--mapstudio-comms-lost` (falling back to `--qual-1`) with the glyph and the word, the icon KPI, the alarm glyph with its digit on a solid badge when unacknowledged and a hollow one when acknowledged (`--mapstudio-alarm-1` to `-3`, falling back to `--error`, `--warning`, `--info`); the default popup opens on a click (header, comms with data age, KPIs, alarms) and stays live while open. The hue tokens go to the engineering review (ER-27) in entry 12.
- The Gateway holds one subscription per project and tag path the kind setups turn on (AD-6), Alarm Metrics by Java subscription; the dev stack's Pad UDT carries a dev-only alarm for it (`ops/config/core`, a fresh volume is needed once: `ops/up.sh --fresh`).
- Basemaps (entry 6, AD-12): the setup's `basemaps` are offered in a control on the map, None (the blank background), OpenStreetMap (its public tiles) and Satellite (Mapbox satellite imagery), each with its provider's attribution always shown; `mapbox` (the vector style) stays deferred. New message types `basemap.source` and `basemap.source.reply`: the Gateway reads the Satellite token from the secret the setup's `tokenSecret` names, only when a browser asks, refuses anything but a public `pk.` token, and sends it only inside the tile URL; new error code `token-unavailable` ([docs/contract.md](docs/contract.md), "basemap.source"; [docs/basemaps.md](docs/basemaps.md)). OpenStreetMap's tile usage policy is in [docs/setup.md](docs/setup.md).
- New component prop `startingArea` (entry 6, R1): `{center: {lng, lat}, zoom, bounds: {west, south, east, north}}`, a centre and zoom or bounds to fit; the default is the whole world. It replaces the component's hard-coded start view of 0.2.0; two components on one page may open on different areas and show the same map items ([docs/contract.md](docs/contract.md), "The component's props").

- Labels, lines and the template's map parity (entry 7, R3, R5): the map's text (item names from zoom 14, the state chip "Stale" or "Comms lost" beside the name, the icon KPI from zoom 15, line name chips) is drawn by MapLibre's symbol layers in a bundled glyph source, Noto Sans SemiBold and Medium (OFL 1.1, [NOTICE](NOTICE)) rendered at build time and served at `/res/mapstudio/glyphs/` ([docs/icons.md](docs/icons.md)), with a halo, colliding and giving way by rank (the selected item, alarms by priority, comms lost, stale, then the kind list's `labelRank`); the marker image is the disc, the kind glyph, the ring and the badge with its digit, and a normal item is a dot below zoom 14 (7 px below 12) while abnormal items keep their marker. Lines take their weight from the `diameter` property with an instrument on them (3, 4, 6 px; 2 px without), a hue only from their own alarm with the glyph at the midpoint, and dash for comms lost or stale; the selected line carries the flow arrow. Points within 20 m draw as one shared marker that opens a pick list (its label names two members, or from three the first two and "+N more", entry 11); Fit and Return sit under the zoom buttons; a tap on the ground clears the selection; Fit keeps until the items' bounds change or the user moves the map. The checklist against the template's map is [docs/map-parity.md](docs/map-parity.md) ([docs/contract.md](docs/contract.md), "What the map draws").

- The View-mode controls as designed (entry 14, R5, R10; DESIGN.md View mode, Phone, zoom-control, legend): one zoom card top-right with plus, the zoom level ("z 15"), minus, Fit and Return as glyphs (Return disabled with nothing selected), a rounded card with the floating shadow (`--mapstudio-float-shadow`, the host theme's `--boxShadow1` where it has one) and 44 px targets below 768 px; a Legend button bottom-left with MapLibre's scale bar and the provider's attribution beside it, opening a panel (by click or keyboard, Esc closes it) whose Basemap section holds entry 6's basemap choice, built from sections so entry 3 adds the glyph key and the Lines and Names toggles; nothing in the bottom-right corner. - Instruments drawn on lines, the ordered line popup, segment click and the aggregate line style (entry 2, R13; AD-7, AD-11, AD-16, AD-19; [docs/instruments.md](docs/instruments.md)): an instrument (a map item of an instrument kind with an `attachment`) draws as its kind's marker at its place on its line, with a 24 px disc, its name, chip, KPI and its own alarm badge, so an instrument's alarm draws at its place while the line's own alarm keeps the midpoint badge; a line with instruments is cut in the browser at its measuring instruments (those whose kind setup has an icon KPI; a line valve bounds no segment) into one feature per segment. ## 0.2.0

The map store and its data (epic-map-store-and-data). Contract 0.2.0; project setup schema 1; map store schema 2. Requires Ignition 8.3 and a PostgreSQL connection per project.

### Contract changes

- New message types: `map.load` and `map.load.reply` (level, change sequence, map items, kind and asset lists, adapter status, read-only reason, the browser's part of the setup, `kindSetups` (levels `phone` and `full` only) and the optional `user`, the session user name), `edits.apply` and `edits.apply.reply` (one all-or-none batch of versioned ops), `map.changed` (every committed batch, to every open map of the project), `tags.browse`, `tags.browse.reply`, `tags.resolve` and `tags.resolve.reply` (the tag browser's lookups, full editors only).
- `error` (0.1.0) may now carry `batchId`, `op: {index, id}` and `conflicts`. New error codes include `conflict`, `role`, `read-only`, `store-unreachable` (also the busy reply) and `tags-unavailable`; `stale` is reserved. The full list is in [docs/contract.md](docs/contract.md), "Error codes".
- The map item record (AD-20), closed: `id`, `kind`, `name`, `geometry` (GeoJSON `Point` or `LineString`, WGS 84), `properties`, `assetId`, `overrides`, `ends`, `attachment` (schema 2), `version`, `deleted`.
- The project setup, schema version 1 ([docs/setup.md](docs/setup.md)): a project resource naming the map store connection, the full and phone editing roles, the kind and asset functions, basemaps, refresh interval, alarm page and token secret (`<provider>/<name>`, a name only).
- The kind list and asset contract ([docs/kinds-and-assets.md](docs/kinds-and-assets.md)) and the kind setup schema ([docs/kind-setup.md](docs/kind-setup.md)), including popup view params and `{asset.path}/...` tag paths.
- The scripting API `system.mapstudio`: `getMap`, `applyEdits`, `refreshAdapters`, `ping`.

### Map store migrations

- Migration 1 creates the `mapstudio_` tables on the first start (needs CREATE on the connection's schema).
- Migration 2 (story 14) adds `mapstudio_item.attachment` and two indexes. `ALTER TABLE` needs the role that **owns the `mapstudio_` tables**, not the least-privilege runtime role: start the upgraded module once with the owner's role on the connection, or give the tables to the connection's role first. Until then the map store is unavailable with an error naming `migration 2` and SQLState 42501, and nothing is changed. Take a backup first ([docs/operations.md](docs/operations.md)).
