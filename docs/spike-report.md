## Pending the owner

These are the five items no agent session could produce. Each names the exact step; none is guessed above.

1. **A GPU-accelerated frame-rate run (NFR-1).** The owner's headed run on 2026-10-26 is recorded in the table: Playwright's Chromium still reported SwiftShader (software WebGL) and every run sat at a 33.3 ms frame interval, so it measured a frame cap, not the GPU. The next step is a run in a GPU-accelerated browser on a 60 Hz display: `chrome://gpu` must show hardware acceleration for WebGL (Playwright's bundled Chromium may need `PW_CHROMIUM_PATH` pointed at the system Chrome, or launch flags that enable the GPU; a VM or a remote desktop session usually cannot), then with the dev Gateway up (`ops/up.sh`): `cd e2e && npm ci && npx playwright install chromium && E2E_HEADED=1 npm test`. The suite writes `e2e/out/measures.json` with the renderer string in `env.renderer` and the pan and zoom fps for `scale30`; with `E2E_DOCS=1` it rewrites `docs/spike-measures.json`. A renderer string that is not SwiftShader and a p50 interval under 33 ms are the signs it measured what NFR-1 asks. The stand-in data draws circles and lines only, so even a pass is a floor, not the final verdict (risks below).
2. **Designer autocomplete of `system.mapstudio.`.** In the Designer on a dev Gateway running the current build, type `system.mapstudio.` in the script console: the functions `ping` and `echo` should autocomplete with the descriptions from `MapStudioScriptModule.properties`. Record yes or no in the `system.mapstudio` row.
3. **`CHECK setup-modified` on v0.1.0.** The code behind it was removed by story 8. Run it on the v0.1.0 module (or commit `51104c8`) with `ops/checks.sh`, open the Designer, change and save the `setup` resource of `mapstudio-dev`, and look for `CHECK setup-modified` in `ops/logs.sh`. Record yes or no in the custom project resource row. A no does not block epic 2: the setup can be read at start-up and on a project scan.
4. **Mapbox terms (AD-12).** Read Mapbox's current Product Terms for the Raster Tiles API and `mapbox.satellite` in a non-Mapbox renderer (MapLibre) for client SCADA sites; record allowed or not allowed with the date read. If not allowed, AD-12's alternative is a commercial MapTiler or Esri plan; epic-viewing needs the answer, not this decision.

## If no-go: the built-in Perspective Map

A no-go ends the initiative in favour of a better page on the built-in Perspective Map component (`ia.display.map`, Leaflet) in `ign-scada-template` (prd 6.4; the initiative's constraints). What that page can and cannot be, from the template's current map (`docs/map.md` there, section 5) and the skills' Map Component notes:

- Keeps: markers and lines from `_Model/Map`, the drawing layer and `/map/edit` as they are, the `map_draft` tables and `prov`'s map steps, OSM and Mapbox tiles with the existing token.
- Gains with a no-go's effort: a tidier page (search, fit and return, name toggles) on the Map's own marker, polyline and `customControls` props (a custom control and a marker popup each mount a project view by path, which is what story 4 copied), within the limits the skills record for it (icons on the 24-unit grid, `init` read at mount only, literal colours overridden by stylesheet rules).
- Does not get: in-browser drawing with snapping and undo, kind setups, a map store with conflict detection, one shared Gateway subscription for icon state, a bottom sheet on a phone. Those are the PRD's FR-9 to FR-32 and stay out.
- The template's map pages are not changed by this epic either way (epic Boundaries), so a no-go costs nothing already built there. The released v0.1.0 module and its lock entry would be removed from the template in a follow-up pull request.

## If go: what epic 2 commits to

A go starts epic-map-store-and-data on the answers above as fixed facts:

- **Setup (AD-5):** the custom project resource type works on the Gateway with no registration; epic 2 decides the Designer editor (about 300 lines of Swing from IA's example, or the script-function fallback) and carries the `onResourcesModified` answer the owner records in item 3.
- **Adapters (AD-4) and the scripting API (AD-18):** `getProjectScriptManager` and `initializeScriptManager` are the mechanisms; project functions run on a bounded pool with a timeout because `runCode` is synchronous (AD-1). `system.mapstudio.ping` and `echo` are the scaffold `getMap` and `applyEdits` replace.
- **Map store (AD-3, AD-21):** PostgreSQL through `DatasourceManager.getDatasource(name).getConnection()`; migrations at start-up; a `Valid` connection says nothing about rights, so the start-up CREATE is the only signal and its SQLState 42501 error line is the pattern.
- **Live values (AD-6):** one Gateway subscription per metric per asset through `subscribeAsync`, no reference tags; the `values.batch` message replaces story 7's stand-in and is measured for real then.
- **Seed data:** the 30 pads reach the component through `system.mapstudio.applyEdits`, after which the spike props `testSet` and `scaleData.ts` and the Scale view go (deferred-work, story 8). `popupView` stays until epic-viewing's kind setup (AD-7).
- **Platform pins (NFR-6):** SDK 8.3.0 as the declared minimum, `@inductiveautomation/perspective-client` 2.3.10 against the 8.3.10 dev Gateway, and the template's 8.3.9 image proven to load the module; every 8.3.x upgrade is checked on the test stack.
- **Release path:** signed releases through the `release` environment, the template's lock entry at v0.1.0 (the template pull request is the owner's to merge), and version 0.2.0 for the first epic 2 release that changes the public contract (AD-9).
