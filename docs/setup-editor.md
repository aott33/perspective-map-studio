# Map Studio Setup in the Designer

Each Perspective project that uses Map Studio has one setup (architecture AD-5, setup schema version 1): the project resource `com.aoindustrial.perspective.mapstudio/setup/`, holding `setup.json` and `resource.json`. The schema is in [contract.md](contract.md), section "The project setup", and the fields' rules in [setup.md](setup.md). The Designer edits it in the **Map Studio Setup** tab (epic 2 story 7; laid out again, with lists to pick from, in epic 2 story 16).

## Opening and creating

- Double-click **Map Studio Setup** in the project browser. That is the only way in: the node has no Map Studio menu. The node reads "Map Studio Setup", "Map Studio Setup (none)" when the project has no setup, "Map Studio Setup (new, unsaved)" while a new one waits for File > Save, "Map Studio Setup (unsaved)" while the open tab holds changes the project does not have (the tab's title says the same), or "Map Studio Setup (inherited)".
- A project with no setup opens the tab in its empty state: "No Map Studio setup" and one **Create setup** button. There is no create dialog. Create setup fills the same form with the defaults (full-editing role `MapEditor`, phone-editing role `MapOperator`, refresh every 10 seconds, basemaps `none` and `osm`, everything else empty), marked "New setup - saves with the project", and puts the cursor in Database connection. Nothing is written until File > Save; **Discard new setup** in the footer returns to the empty state.
- A project that inherits its setup shows "Inherited from <project>"; saving makes this project's own copy. When the parent does not allow overriding it, the form is read only.

## The form

The tab holds one form, at most 760 px wide and left aligned, in four sections: Map store, Who can edit, Kinds and assets, Map. On a narrow tab each label moves above its control and the form wraps; there is never a horizontal scroll bar. The header shows "Map Studio Setup", a **Refresh lists** link and "Schema version 1" as text (never a field). Help is in each label's tooltip (and is the control's accessible description); the one line under a field is under Map token: "Names only - the Designer never reads the token."

| Field | `setup.json` key | Control | List |
| --- | --- | --- | --- |
| Database connection | `connection` | The Designer's editable combo box | The Gateway's database connections, each with its type |
| Full-editing roles | `roles.full` | Chips above an editable combo box: picking a role or Enter adds it, Backspace in the empty input removes the last, each chip's cross removes it | The roles of the project's identity provider |
| Phone-editing roles | `roles.phone` | As above | As above |
| Kinds function | `kindsFunction` | Editable combo box, monospace | The project library's (`ignition/script-python`) top-level functions as `package.function` (names starting with `_` are not offered) |
| Assets function | `assetsFunction` | As above | As above |
| Refresh interval | `refreshIntervalSeconds` | The Designer's number spinner, "seconds"; its arrows step the typed number; any text can be typed | none |
| Basemaps | `basemaps` | Checkboxes None, OpenStreetMap, Satellite, Mapbox (and a box for any other name in the file, so it can be unticked) | fixed |
| Alarm page | `alarmPage` | Editable combo box, monospace | The page URLs of the project's page configuration, then **Insert placeholder...**, which inserts `{item.id}`, `{item.name}`, `{asset.id}`, `{asset.path}` or `{item.properties.<field key>}` at the cursor. A picked URL with a `:param` gets `{item.name}` there, selected |
| Map token | `tokenSecret` | Secret provider combo box and secret name combo box; saved as `<provider>/<name>` | The Gateway's secret providers, then the chosen provider's secret names |

Every list is a suggestion: anything can be typed, and it is saved as typed. Gateway lists load when the tab opens and with Refresh lists, off the Swing thread; project lists are read from the open project. A list that fails (no Gateway, a refusal, a Gateway module without the setup RPC, an identity provider that does not list its roles) stays empty, with no message: typing still works, and the Designer itself shows when it has no Gateway connection (owner, 2026-10-27).

The dropdowns and the spinner are the Designer's own controls (owner, 2026-10-27, compared with Project Properties > Project > General): plain `JComboBox` and `JSpinner` drawn by the Designer's look and feel (Synthetica, `ignition-laf`, in 8.3 **[observed in the 8.3.10 image]**), with no UI delegate, arrow button, border or background of Map Studio's. The list's lines are the look and feel's own renderer given the words; the placeholder ("Select one...") is painted over the empty editor by a `JLayer` and is never the value; "Insert placeholder..." runs when chosen and never becomes the value. The Designer's look and feel has no placeholder property (Synthetica's client properties have none) **[observed in the 8.3.10 image]**.

**Reasons** stop the save: the input checks (a connection is named, the interval is a whole number, a function is `package.function`, nothing is listed twice) and the Gateway's own setup reader's messages (`common/.../contract/Setup.java`), each beside its field, so a setup the form accepts is one the Gateway reads. **Warnings** never stop it and come only from a list that loaded: a connection the Gateway does not have yet, a connection that is not PostgreSQL, a role the identity provider does not have, a function not in the project library, a page not in the page configuration, a secret provider or secret name the Gateway does not have, Mapbox ticked with no token, a token with no provider. A reason shows under its field with the error glyph; a warning shows under it with the warning glyph, and the glyph beside the field; nothing marks a field that is fine. No control is recoloured: the Designer's combo box and spinner keep their look (fix 16).

The **footer** shows only when it has something to say: "N reasons left - this setup is not saved until they are fixed." as plain text (no link, nothing to scroll to: the form is short, owner 2026-10-27) with the warning count; or, for a new setup, "New setup - not saved yet." or its reasons with "File > Save saves the rest of the project without it.", and Discard new setup. There is no Gateway-not-reachable footer, banner or Try again (owner, 2026-10-27). When a Gateway list failed, its warnings are not shown (nothing to compare with), and functions and pages still list; the header's Refresh lists asks again.

Reading a file follows the Gateway: a refresh interval written as text (`"10"`) makes the file unreadable here; `15.0` shows as `15`; `"basemaps": null` means no basemaps; a file the Gateway refuses is never shown as one it would read. The form is stricter in one place: `10.5`, which the Gateway cuts to `10`, is shown as written and asked to be a whole number.

## The Gateway lists, names only

The lists come from the module's own RPC, `SetupLookupRpc` (package `mapstudio-setup`), answered by the Gateway's `SetupLookups`: connection names and types, the role names of the user source named like the project's identity provider (an identity provider without one, such as OIDC or SAML, "does not list its roles"), secret provider names and one provider's secret names. Each list answers within 5 s or is unavailable on its own. Each list has at most one call in flight (a later ask waits on it again), and secret names run on threads of their own, so a secret provider that hangs holds one thread and never the connections or roles. It never reads, returns or logs a secret's value; only a Designer session may call it (it is not offered to a Vision client, and the module refuses any other caller). Owner decision 2026-10-27: any user who can open the Designer may see these names.

## Saving

- The setup is saved with the project (File > Save): at each project save the module commits the open setup tab (and a new setup), and the tab compares the form with the setup it read, so typing alone needs no change mark. A field edit alone saved the setup in the owner's session **[owner, seen in the Designer 2026-10-27]**.
- **Only the setup is held back** when reasons are left (owner, 2026-10-27, fix 16). The rest of the project saves; nothing of the setup is written; the setup tab keeps its changes and reasons, comes forward (a new setup's tab is reopened if it was closed), and its tab and node read "(unsaved)" ("(new, unsaved)" for a new setup). No dialog, and no save failure. One line goes to the Designer's log (`MapStudio.designer`): "Map Studio setup of project <project> held back from this save; the rest of the project is saved. Reasons: ...". How: `SetupEditor.getObjectForSave()` hands back the setup as read, which `ResourceEditor.commit()` does not write when `isOptimizeCommits()` and the object equals the one read ("Avoiding commit - resource has not changed."); a new setup is simply not created; `notifyProjectSaveStart` returns normally. Throwing instead, as story 16 did, makes the Designer's module commit task return false, show "Error encountered in module "Map Studio" while saving." and stop the whole save **[SDK 8.3.0 javap: `ResourceEditor.commit`, `IgnitionDesigner.commitAll`, `handleSave`]**. Seen in a Designer: **[unverified]**, the owner's re-check. Two consequences of the SDK, also **[unverified]**: the Designer does not know the setup is unsaved (the setup has no change in the project), so its own unsaved-changes prompt on close does not count it; and closing the setup tab commits it first (`TabbedResourceWorkspace.close`), so a tab closed with reasons left drops its changes, as nothing of it can be written.
- A new setup is dropped, not saved, when the project has a setup by the time of the save (for example one pulled in from another Designer's save), so it never overwrites that setup.
- `setup.json` is written as 2-space indented JSON, the known keys in the order of the schema, lists of names on one line, then any keys the form does not know unchanged, with a newline at the end. Saving an unchanged setup writes nothing, and an unchanged `tokenSecret` keeps its bytes; a change to one field changes only its line, so a save of the bind-mounted dev project (`ops/project`) gives a small git diff. Revert or commit such a diff on purpose.
- A setup written by a newer Map Studio (`schemaVersion` above 1) is shown as written, read only, under "Schema 2 - read only", and never rewritten.
- A `setup.json` that is not readable is shown as written with the reason and a **Start from defaults** button, which asks first; the file is replaced only at the next project save.

## How a save reaches the Gateway

The Gateway reads the setup when the project starts (story 1) and again when the project changes (story 6), so a saved change applies without a restart. A missing or unreadable setup leaves the project's map store unavailable, and `map.load` answers `store-unreachable` with the reason ([contract.md](contract.md)).
