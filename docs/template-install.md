# Install through the template's module lock

Story 6 (epic-module-foundation R5): the signed Map Studio release v0.1.0 installs on the `ign-scada-template` test stack through its `modules/modules.lock.json`, pinned by SHA-256 and certificate fingerprint, and a scratch Perspective project shows the map. Date: 2026-10-26. The proof ran twice: first as a rehearsal with a locally signed throwaway build (before the release existed), then against the real published release. Only the real release's values are in the template's lock entry.

Labels: **[live 8.3.9]** seen on the template's test stack (`inductiveautomation/ignition:8.3.9`, the image the template pins); **[build]** seen in this repository's scripts; **[template code]** read from `ign-scada-template` source; **[not verified]** not checked here. Findings (none changes module behaviour in the version pull request):

- **`module_version` is `dev` in a signed build.** `mapstudio_schema_version` recorded `dev` for both migrations: `MapStudioServices.moduleVersion()` reads the gateway jar's `Implementation-Version`, and no jar's manifest carries one. Only that audit column is affected, but `module_version` is part of the public contract (`docs/contract.md`, the map store schema) and a row written by a published 0.2.0 cannot be corrected later. Under the plan's rule (a defect found here stops the release and becomes its own fix) this blocked the tag. **Fixed before the tag (owner decision 2026-10-27, plan Decision 9, gate G4 cleared):** the root build writes `Implementation-Version` = the Gradle version into every module jar's manifest (the tag in a release, `x.y.z-SNAPSHOT` locally), `ModuleVersion` reads it (the package's version, else the manifest of the jar the class came from; `dev` only for a class outside a jar), `GatewayJarManifestTest` fails when the gateway jar's manifest lacks the attribute and `MigratorTest` checks the migrator records the version it is given. A build with `-PreleaseVersion=0.2.0`, as `build-signed.sh` passes the tag, shows `Implementation-Version: 0.2.0` in `gateway-0.2.0.jar` inside the `.modl` **[build]**; the published release's rows are checked on the real stack (owner steps). The `dev` rows of the rehearsal stay in the throwaway stack only.
- **A second tab arms no replay timer for another tab's entry.** `UnsavedSender.storage()` refreshes the list (as `docs/contract.md` says) but does not start the 15 s replay timer, so a tab that only learnt an entry from a `storage` event replays it on its next `map.load`, `map.changed` or Try again, not on its own. With the first tab closed and no other save on the project, the entry waits until then. Recorded in `_bmad-output/deferred-work.md` for epic-editing.
- **A scratch project copied without `global-props/data.bin` does not start in Perspective** on 8.3.9: the first scan logs `Error creating dataFile ... global-props/resource.json, file=data.bin` and a `NullPointerException` (`existingGlobalProps` is null) in `PerspectiveProjectCacheImpl`; the `PUT` of the project record then writes `data.bin`, but the project starts only after it is removed and scanned in again. Copy a project without its `global-props` folder at all. **[live 8.3.9]**
- **A database connection resource written by hand needs `attributes.uuid`**: without it the scan logs `Resource ignition/database-connection/MapStudio does not have required UUID attribute, will not be loaded`, although `resources/list` names it. **[live 8.3.9]**

## The rehearsal (before the release existed)

A throwaway PKCS#12 keystore signed a v0.1.0 build with `scripts/ci/build-signed.sh`; a throwaway clone of the template got a lock entry with the throwaway SHA-256 and fingerprint, on a branch that was never pushed; `stack.sh` ran twice with the same render limits and the scratch project showed the map as above. No throwaway value was written in this repository or in any pushed branch.

- **Finding: the certificate bundle must be PKCS#7.** The first throwaway build failed the template's `modl.py inspect` with a traceback from `openssl pkcs7`: the Gradle plugin copies the configured certificate file into the module as `certificates.p7b` without converting it, and `build-signed.sh` gave it the PEM certificate that `keytool -exportcert -rfc` writes, a bare certificate rather than a PKCS#7 bundle. `build-signed.sh` now wraps the certificate in a PKCS#7 DER bundle (`openssl crl2pkcs7`), as the other vendors' modules ship it; `modl-verify.sh` refuses a `certificates.p7b` that `openssl pkcs7` cannot read (and fails if openssl is missing); `scripts/ci/test-signing.sh` has a negative case for a bare certificate. The v0.1.0 release carries the fix. Whether a Gateway would also accept the bare certificate was not tested **[not verified]**.
- **Rehearsal stack runs.** Run 1 exited 1 at the render suite on one check, `phone-native-night /well/Mesa/P12/P12-3H/trends` (`Cannot subscribe to "ProjectDefinition" state. "Parts/Asset/Trends/" does not exist`, an embed path whose type segment was still empty). The same page passed in `native-day`, a re-run of the whole `phone-native-night` pass on the same stack passed, and a fresh run (run 2) passed; the real-release run above also passed. No Map Studio view is on that page, so it looks like an existing template race **[not verified]**: not reproduced without the module. It is a deferred item for `ign-scada-template` (`_bmad-output/deferred-work.md`).
