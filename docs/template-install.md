# Install through the template's module lock

Story 6 (epic-module-foundation R5): the signed Map Studio release v0.1.0 installs on the `ign-scada-template` test stack through its `modules/modules.lock.json`, pinned by SHA-256 and certificate fingerprint, and a scratch Perspective project shows the map. Date: 2026-10-26. The proof ran twice: first as a rehearsal with a locally signed throwaway build (before the release existed), then against the real published release. Only the real release's values are in the template's lock entry.

Labels: **[live 8.3.9]** seen on the template's test stack (`inductiveautomation/ignition:8.3.9`, the image the template pins); **[build]** seen in this repository's scripts; **[template code]** read from `ign-scada-template` source; **[not verified]** not checked here.

The release is `aott33/perspective-map-studio` tag v0.1.0 (assets `Map-Studio-0.1.0.modl` and `Map-Studio-0.1.0.modl.sha256`), signed by the release workflow with the owner's certificate; its fingerprint is the README's "Signing certificate SHA-256" line. In a fresh clone of the template (one new branch, nothing pushed from here):

1. **The lock entry** (shape in [RELEASING.md](../RELEASING.md), "Installing through a host's module lock"): `url` is the github.com release URL, `sha256` the published `.sha256` file's value, `certSha256` the README fingerprint, licence Apache-2.0, `upstream` type `github` with the repository and the asset pattern. `docs/modules.md` (module table, history, "five modules from three vendors") and `THIRD_PARTY_NOTICES.md` list it. 2. **Public fetch with no credential: worked.** `python3 -I scripts/modules/modl.py fetch` downloaded the asset from the github.com URL and printed `ok com.aoindustrial.perspective.mapstudio 0.1.0 (6 signatures)`. The template's `download()` sends no credential (`http_get(url)` with no token; only the update check's releases listing reads `GITHUB_TOKEN`) **[template code]**, and an unauthenticated `curl` of the `.sha256` asset also answered HTTP 200; the session's shell did have a GitHub token in its environment, so the claim rests on that code reading, not on an empty environment. 3. **Checks on the download:** `modl.py inspect` (6 signatures checked, none bad, subject `O = AO Industrial, CN = Map Studio`, fingerprint equal to the README); `sha256sum` equal to the `.sha256` file; `scripts/ci/modl-verify.sh` with the README fingerprint and version 0.1.0 printed the module id, version and the same fingerprint; the archive's `certificates.p7b` is a DER PKCS#7 bundle (`file`). Template checks: `modl.py verify-lock` (`lock ok`), `check_repo.py --jython tools/jython.jar` (1751 files, 0 errors), `gen/check.py` (generators match: 438 project files, 162 views).
4. **`scripts/test/stack.sh --keep` on the committed branch: `test stack: PASS`, exit 0, no FAIL line.** Render limits as the template's CI uses for its fieldsim job (`RENDER_PASSES=native-day,phone-native-night`, `RENDER_ROLES=engineer`); a local run without them covers every pass and all five roles, which was not done. ## The rehearsal (before the release existed)

A throwaway PKCS#12 keystore signed a v0.1.0 build with `scripts/ci/build-signed.sh`; a throwaway clone of the template got a lock entry with the throwaway SHA-256 and fingerprint, on a branch that was never pushed; `stack.sh` ran twice with the same render limits and the scratch project showed the map as above. No throwaway value was written in this repository or in any pushed branch.

- **Finding: the certificate bundle must be PKCS#7.** The first throwaway build failed the template's `modl.py inspect` with a traceback from `openssl pkcs7`: the Gradle plugin copies the configured certificate file into the module as `certificates.p7b` without converting it, and `build-signed.sh` gave it the PEM certificate that `keytool -exportcert -rfc` writes, a bare certificate rather than a PKCS#7 bundle. `build-signed.sh` now wraps the certificate in a PKCS#7 DER bundle (`openssl crl2pkcs7`), as the other vendors' modules ship it; `modl-verify.sh` refuses a `certificates.p7b` that `openssl pkcs7` cannot read (and fails if openssl is missing); `scripts/ci/test-signing.sh` has a negative case for a bare certificate. The v0.1.0 release carries the fix. Whether a Gateway would also accept the bare certificate was not tested **[not verified]**.
- **Rehearsal stack runs.** Run 1 exited 1 at the render suite on one check, `phone-native-night /well/Mesa/P12/P12-3H/trends` (`Cannot subscribe to "ProjectDefinition" state. "Parts/Asset/Trends/" does not exist`, an embed path whose type segment was still empty). The same page passed in `native-day`, a re-run of the whole `phone-native-night` pass on the same stack passed, and a fresh run (run 2) passed; the real-release run above also passed. No Map Studio view is on that page, so it looks like an existing template race **[not verified]**: not reproduced without the module. It is a deferred item for `ign-scada-template` (`_bmad-output/deferred-work.md`).
